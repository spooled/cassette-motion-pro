# v0.90.0 release-candidate test plan

This candidate keeps the fit-day path simple: client/session, Kinovea capture or analysis, measurements and evidence, then report/package. It does not replace the fitter's judgment or Kinovea's native capture, playback, and drawing tools.

## Automated gate

On GitHub Actions, confirm **Build solution**, **Check session compatibility and recovery**, **Verify and stage x64 video assemblies**, and **Upload portable application** pass. The installer may be unavailable if the external NSIS download fails; in that case test the portable artifact and do not describe an installer as delivered. The recovery check uses temporary test data only; it does not open or modify a real client.

## Windows fit-day acceptance checks

Use a disposable test client; make a separate copy of any real client data before testing an upgrade.

1. Launch the portable app. Open **Fit Day Dashboard → Getting Started**. Confirm the guide is readable at your normal screen resolution and points to Intake first.
2. Create a test client and session, close the app, reopen it, and confirm the client, session title, goals, and notes remain.
3. Open an older client/session folder made with a previous version. Confirm the session appears and its existing videos, images, measurements, and report settings are unchanged. Do not overwrite the only copy of legacy data.
4. Run **Practice Mode** and **Fit-Day Diagnostics**. Confirm both cameras can record to practice folders, playback opens, and diagnostics shows no unexplained FAIL items.
5. In the test session, record Before and After clips; confirm native Kinovea drawing/playback tools remain available, save a Before and After image, then reopen the session and verify media paths and evidence.
6. Enter or approve a measurement, generate and preview a report, and confirm the selected images, measurements, and fitter notes appear correctly. Review the client-ready PDF before delivery.
7. Change test-session notes, close and reopen the app, and verify the latest complete save. Simulate an interrupted fit by leaving a recoverable draft, restart, and confirm the recovery prompt restores the expected session without changing another client.
8. For a **copy of the test session only**, save twice, damage the copy's `session.xml`, then reopen the copied client. Confirm the prior complete `session.xml.bak` loads. Restore the untouched original after the test; never corrupt a real client folder.
9. Check the portable ZIP on a second Windows computer if available. Confirm startup, camera detection, video playback, and report export without assuming the installer is present.

## Go / no-go

Ship only when the Windows build and automated gate pass, the manual checks above pass on the actual fit-day hardware, and a restorable external backup of client data exists. Record any failed step, Windows version, camera model, and diagnostic report before release. If a failure concerns saving, recovery, media routing, or report accuracy, hold the release candidate.
