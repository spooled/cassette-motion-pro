# Cassette Motion Pro v1.1.0 test plan

This pass changes the unified fit-day presentation, not the underlying Kinovea capture, playback, drawing, measurement, or save behavior.

## 1. Unified visual shell

1. Launch Cassette Motion Pro and open a client from the toolbar.
2. Confirm the Fit Panel uses the updated dark-green, lime, white, and soft-gray visual system.
3. Confirm text, buttons, tabs, and status cards remain readable at the laptop's normal Windows scaling.
4. Resize the main window narrower and confirm the Fit Panel remains usable without hiding the video workspace.

## 2. Stage navigation

1. Use the new **Fit Day**, **Client**, **Video**, **Measurements**, and **Report** stage buttons.
2. Confirm each button opens the expected existing workspace page.
3. Confirm the selected stage is visually clear.
4. Open Client Files, Client History, measurement review, and Report Builder from their existing tabs and confirm the correct main stage stays highlighted.

## 3. Persistent header

1. Open or create a fit session.
2. Confirm the header clearly shows the active client, session, Before/After media, autosave status, and next action.
3. Use **Hide Fit Header** and **Show Fit Header** and confirm the active session remains open.
4. Use **Review** and **Do Next** and confirm both actions still open the expected embedded workspace.

## 4. Fit-day regression checks

1. Record or import Before and After video and confirm capture/playback still receives the available center area.
2. Use Kinovea drawing and measurement tools on a video.
3. Save a Before, After, and Dual image or video to the active client session.
4. Enter or approve measurements and confirm autosave status updates.
5. Open Report Center, preview the PDF, and prepare a delivery package.
6. Close and reopen the session and confirm the saved state is restored.

## Pass condition

The milestone passes when the unified shell is visibly cleaner on the fit-day laptop, all five stage buttons navigate correctly, small-window scrolling remains usable, and the capture-to-report workflow completes without a behavior change.
