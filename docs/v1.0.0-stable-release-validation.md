# v1.0.0 Stable Unified Release — Validation and Sign-off

Version 1.0.0 is a release-hardening milestone. It does not replace fitter judgment or Kinovea’s capture, playback, and drawing tools. Sign off only after the automated Windows build and a complete fit-day rehearsal pass.

## Automated GitHub Actions gate

The release workflow must pass all of these steps:

- Build the x64 solution.
- Load a legacy session and verify current-session round-trip saving.
- Recover a damaged session manifest from its backup.
- Recover a damaged autosave from its backup and clear recovery files safely.
- Verify all source, executable, report, and installer version values are `1.0.0`.
- Verify required camera/video DLLs are x64 and present.
- Verify Kinovea drawing and measurement tools are included.
- Inspect the portable ZIP for the executable, DrawingTools, and portable AppData marker.
- Build the installer when NSIS is available, verify its version, install it silently into a disposable folder, confirm key runtime files, and run its uninstaller.
- Produce `RELEASE-CHECKSUMS.sha256` and `RELEASE-VERIFICATION.txt` in the Windows bundle.

If NSIS is temporarily unavailable, the portable build may still pass, but the stable installer is not signed off until a later run produces and smoke-tests it successfully.

## Upgrade validation

Use copies of existing client data—never the only copy.

1. Back up all client and studio data from the prior installed build.
2. Install v1.0.0 over the prior version and reopen the application.
3. Confirm existing clients, archived clients, sessions, templates, camera profiles, and studio branding remain available.
4. Open an older session and verify goals, notes, Before/After media paths, measurements, favorite frames, selected images, approvals, follow-up entries, and report settings.
5. Generate a report from the upgraded copy and compare it with the prior report.
6. Restore the full backup to a disposable test location or computer and confirm it is readable.

## Recovery validation

1. Create and save a disposable fit session twice.
2. Close the application during an unsaved edit and verify the recovery prompt returns to the expected session and stage.
3. On a copy only, damage `session.xml`; confirm `session.xml.bak` loads the prior complete save.
4. Confirm recovery for one client never changes another client’s session.
5. Confirm clearing recovery removes only the draft and does not remove the saved session, videos, images, or reports.

## Installer and portable validation

1. Download the installer and Windows bundle from the same successful workflow run.
2. Compare their SHA-256 hashes with `RELEASE-CHECKSUMS.sha256`.
3. Install on the studio Windows laptop. Confirm the Start menu shortcut, application launch, version `1.0.0`, camera plugins, playback, DrawingTools, and uninstaller.
4. Launch the portable ZIP from a separate folder and confirm its client data remains within its portable AppData context.
5. Uninstall the installed copy and confirm client data is not deleted unless the uninstall flow explicitly asks and the tester approves deletion.

## Complete real fit-day rehearsal

Use a test rider or disposable client record on the actual studio laptop, cameras, trainer, and display resolution.

1. Create the client and session before capture.
2. Configure both cameras and record multiple Before clips.
3. Open dual playback, confirm synchronization, and use the native drawing/measurement tools.
4. Save Before images, videos, favorite frames, and measurement evidence into the active session.
5. Make a documented test adjustment, then record and save After media.
6. Complete bike and rider measurements; verify warnings, tracking corrections, calibration, and repeatability summaries.
7. Use the integrated measurements/evidence review and Report Center without leaving the main window.
8. Hide and show the persistent header and Fit Panel; confirm the active client/session remains correct.
9. Edit recommendations, choose report images, preview the report, save a PDF, approve it, and prepare the package and ZIP.
10. Close and reopen the app; verify the session, evidence, approval state, report, and delivery files remain correct.

## Release decision

Ship v1.0.0 only when every sign-off row passes, the installer was produced and smoke-tested, the actual studio hardware rehearsal passes, and a restorable external client-data backup exists. Any failure involving client data, media routing, measurements, recovery, or report accuracy is a release blocker.
